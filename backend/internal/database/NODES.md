# Persistência de providerNodes — lote parcial

`Nodes` porta `src/lib/db/repos/nodesRepo.js`: listagem filtrada por tipo, consulta por ID, criação/upsert, atualização por mesclagem transacional e exclusão com retorno do registro removido. Campos extras ficam no JSON `data`; colunas estruturadas prevalecem na leitura. Timestamps seguem ISO UTC com milissegundos.

O pacote está ligado a GET/POST /api/provider-nodes, além de HEAD/OPTIONS, sob o middleware de autenticação existente. Não cria tabelas e não executa migrations: schema ausente retorna erro (inclusive em instalações novas enquanto migrations não forem portadas). Testes usam banco descartável com a definição de tabela da origem.

PUT/DELETE /api/provider-nodes/{id} agora estão registrados: atualização propaga prefix/baseUrl/nodeName/apiType às connections preservando campos específicos adicionais; exclusão remove as connections associadas antes do nó. Como na origem, as operações usam transações separadas e podem deixar alterações parciais quando uma escrita falha; erro retorna 500, não sucesso fictício.

Connections porta consulta por ID, listagem/filtro/ordenação, mesclagem com reset de saúde quando testStatus=active, reordenação ao atualizar prioridade e exclusão por provider. Criação/upsert de connections agora preserva as regras de identidade: nome para API key; machineId para Cursor; e-mail/workspace/username para OAuth; Codex sem workspace não é colapsado; access_token nunca é deduplicado. Preserva createdAt no upsert, aplica reset de saúde e atribui prioridade MAX+1 quando ausente. Criação por API key agora consulta apenas as connections com mesmo provider/authType/nome, mantendo MAX(priority)+1 no SQL; deixa de carregar o pool inteiro nesse caminho. OAuth continua consultando o pool para comparar identidade no JSON, como na origem. Não houve benchmark de imports grandes. Bulk, exclusão individual e reordenação explícita agora estão disponíveis. Bulk aceita 1–500 itens, retorna erros por item para campos obrigatórios ausentes, preserva extras/credenciais no upsert e reordena os providers envolvidos no mesmo commit. Erro SQL/JSON reverte o lote inteiro; teste confirma rollback de um item anterior bem-sucedido. Cleanup também está portado: remove somente campos nulos da lista original e providerSpecificData vazio, preservando timestamps, prioridade e campos desconhecidos. Mantém inclusive a contagem repetida de email NULL (coluna estruturada) da origem. Ainda faltam os contratos HTTP de providers e a homologação diferencial completa. Entradas com provider não string no bulk retornam erro explícito (o contrato HTTP esperado usa IDs string; paridade de tipos arbitrários não foi homologada). A rota de validação de nós e catálogo/normalização de providers também seguem pendentes.

ProxyPools agora porta o repositório de persistência: CRUD, filtros isActive/testStatus, ordenação por updatedAt, defaults e mesclagem preservando extras. Delete remove fitness e pool na mesma transação. Testes com falha sintética confirmam rollback da exclusão de fitness. CRUD HTTP de proxyPools agora registrado sob o guard: coleção GET/POST, item GET/PUT/DELETE, HEAD/OPTIONS. Listagem suporta isActive/includeUsage e conta cada connection uma única vez por pool; exclusão em uso retorna 409 com boundConnectionCount. Testes pelo roteador com SQLite cobrem criação, validações, update, filtro, uso e exclusão. Não testa proxies reais nem cria schema. Rotas de teste de conectividade, fitness repo completo e migrations seguem pendentes. Como na origem, a verificação de vínculo e a exclusão são operações separadas (não há garantia contra vinculação concorrente entre elas).

Correção do acompanhamento: rotação de segredo JWT não é requisito de paridade identificado no backend original; não será acrescentada sem requisito específico. Limpeza global do limiter também não existe na origem e é melhoria opcional, não bloqueio da migração. Isso não elimina as divergências e pendências já documentadas em `../auth/README.md`, nem equivale a uma auditoria de autenticação aprovada.

Validação deste lote: suíte completa, `go vet`, build e `go test -race` aprovados em sandbox sem rede. Testes cobrem CRUD no SQLite, filtro, registros ausentes, mesclagem/preservação de extras e falha com schema ausente. Testes HTTP pelo roteador com SQLite descartável cobrem 401, validações 400/500, criação 201 dos três tipos, prefixos de ID, normalização de URLs, listagem, HEAD e OPTIONS. Sem comparação diferencial Node/Go completa nem validação com servidor TCP nesta atualização.
